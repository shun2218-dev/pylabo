# コースロードマップ

今後追加するコースの候補と、その優先順位をまとめたものです。

判断の軸は **「実務で詰まる頻度 × 独学で身につきにくさ」** です。文法は本や記事で拾えますが、テストの書き方・型の運用・環境の切り分けあたりは、体系立てて教わる機会が少ないわりに現場で毎日効いてきます。そこから先に埋めます。

## 採用済み（アプリに「追加予定」として表示中）

| 順 | コース | レベル | ねらい | 収録予定 |
|---|---|---|---|---|
| 1 | **テストと品質** | 実践 | 壊れたらすぐ気づける状態を作る。書き捨てスクリプトから抜け出す最初の一歩 | pytest の基本 / フィクスチャとパラメータ化 / モック / カバレッジの読み方 / テストしやすい設計 |
| 2 | **型ヒントと静的解析** | 実践 | 実行前に間違いを見つける。型を「設計の道具」として使う | typing の実用パターン / mypy・pyright / ruff / Protocol による疎結合 / 既存コードへの段階導入 |
| 3 | **データベースと SQL** | 実践 | データの置き場所を扱えるようにする。分析にも開発にも効く | sqlite3 / SELECT・JOIN・集計 / SQLAlchemy / マイグレーション / N+1 とインデックス |
| 4 | **非同期処理と並行実行** | 実践 | 待ち時間の多い処理を速くする。使いどころを実測で判断できるように | async/await / asyncio / httpx で並行リクエスト / threading と multiprocessing / 計測 |
| 5 | **環境とパッケージング** | 実践 | 「自分の環境では動く」を卒業する | venv・uv / pyproject.toml / 自作パッケージ / Docker / GitHub Actions |
| 6 | **CLI ツール開発** | 実践 | 手で動かしている処理をコマンドにして配る | argparse・Typer / 設定と環境変数 / logging / エラー設計と終了コード / 配布 |

順番は「1 つ前のコースの内容を前提にしない」ように組んであり、どれから着手しても構いません。ただし公開順は上から想定しています（テストと型は、他のコースの演習の質を底上げするため）。

## 追加するときの手順

1. `src/courses/registry.ts` に `planned(...)` で告知する（本文はまだ不要）
2. 本文ができたら `src/courses/<name>.ts` を作る
3. `planned(...)` を `available(...)` に書き換える

詳細は [コースの追加方法.md](コースの追加方法.md) を参照してください。

## 1 コースの目安

- **レッスン数** 6〜16。1 レッスンは 5〜10 分で終わる分量
- **章立て** 3〜4 章。最後の章は「卒業制作」として、それまでの内容を組み合わせる
- **演習** 各レッスンに 1 つ。自動採点のチェック項目は 3〜6 個
- **ブラウザで動かせない題材** は「読むだけ」ブロックにし、仕組みの部分は素の Python で自作して動かす
