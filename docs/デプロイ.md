# デプロイ

このアプリは **完全な静的サイト**です。サーバー側の処理は一切なく、`npm run build` が出力する `dist/` をそのまま配信すれば動きます。Vercel / Netlify / Cloudflare Pages / GitHub Pages / S3 など、静的ホスティングならどこでも構いません。

## Vercel の場合

リポジトリを Vercel にインポートするだけです。`vercel.json` に設定を入れてあるので、ダッシュボードでの追加設定は要りません。

| 項目 | 値 | 備考 |
|---|---|---|
| Framework Preset | Vite | `vercel.json` で指定済み |
| Build Command | `npm run build` | 同上 |
| Output Directory | `dist` | 同上 |
| Install Command | （既定） | `postinstall` で Pyodide 一式が用意される |
| 環境変数 | なし | |
| リライト設定 | 不要 | ハッシュルーティング（`/#/c/...`）のため |

### ビルド時に何が起きるか

1. `npm install` → `postinstall` が走る
   - `sync-pyodide.mjs` … `node_modules/pyodide` を `public/pyodide/` へコピー
   - `fetch-pyodide-packages.mjs` … pandas / matplotlib などの wheel を Pyodide 公式配布物から取得（sha256 検証つき）
2. `tsc -b` で型チェック
3. `vite build` で `dist/` を出力（`public/` の中身も `dist/` へコピーされる）

**wheel の取得に 1 つでも失敗するとビルドが失敗します。** 欠けたまま公開すると、データ分析コースが実行時に「パッケージが見つからない」で壊れるためです。ビルドログに失敗したパッケージ名が出ます。

ビルド全体は 1 分程度です（Vercel の上限は 45 分）。

### デプロイサイズについて

`dist/` は約 35MB（うち 34MB が Pyodide ランタイムと wheel）です。

Vercel の「Static File uploads 100MB（Hobby）」という制限は **CLI でアップロードするソースファイル** に対するものなので、Git 連携でビルドする限り関係ありません。ビルド出力のファイル数に上限はありません。CLI（`vercel` コマンド）でデプロイする場合も、`.vercelignore` で `public/pyodide` を除いてあるため、送られるのはソースだけです。

### 帯域は要注意

学習者 1 人あたりの転送量の目安です（初回、キャッシュなしの場合）。

| 何をするか | 転送量 |
|---|---|
| ホーム画面を見るだけ | 約 0.2MB |
| 文法・自動化・アプリ開発コースを開く | 約 **13MB** |
| データ分析コースを開く（pandas / matplotlib） | 約 **29MB** |

Pyodide のランタイムがそのまま流れるため、一般的な Web アプリよりかなり大きくなります。無料枠（Hobby: 100GB/月）だと、**文法コースなら月 8,000 回ほど、データ分析コースなら月 3,400 回ほど**が目安です。

社内やごく少人数で使うぶんには問題ありませんが、広く公開する場合はこの点を見込んでおいてください。`vercel.json` でキャッシュヘッダーを設定してあるので、2 回目以降の訪問では転送はほぼ発生しません。

## そのほかのホスティング

### GitHub Pages などサブパスに置く場合

`https://example.com/python-lab/` のようにサブディレクトリへ置くときは、`vite.config.ts` に `base` を足してください。Pyodide の読み込み先は `import.meta.env.BASE_URL` から組み立てているので、これだけで追従します。

```ts
export default defineConfig({
  base: "/python-lab/",
  // ...
});
```

### 必要なサーバー設定

- **リライトは不要**（ハッシュルーティングのため、常に `/` が返れば動きます）
- `.wasm` を `application/wasm` で返せること（多くのホスティングは既定で対応しています）
- 特別なヘッダー（COOP / COEP）は不要です。このアプリは SharedArrayBuffer を使いません

### 手元で本番同等の確認をする

```bash
npm run build
```

```bash
npx serve dist
```

`vite preview` ではなく素の静的サーバーで開くと、ホスティング環境に近い状態を確認できます。
